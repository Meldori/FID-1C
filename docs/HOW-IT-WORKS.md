# FID-1С: как это работает

FID-1С переносит клинику из 1С в Future IT Dent (FID) и **доказывает**, что перенесено всё: после загрузки каждая запись 1С сверяется с базой, и в конце пишется «совпало N из M».

Это один набор файлов, который подключается к Claude, ChatGPT/Codex или запускается вручную из консоли.

## 1. Идея в одном абзаце

Загрузить данные нетрудно, трудно узнать, что ничего не потерялось. Задачи импорта FID молча пропускают строку, если не нашли пациента или врача, и сообщения об ошибке не будет. Поэтому процесс устроен так: проверить файл, загрузить в **тестовый** тенант, сверить построчно с исходным XML, показать итог. В рабочую базу переносим только то, что сошлось, и только по явному согласию человека.

## 2. Три шага и три отчёта

```
 выгрузка 1С (.zip/.rar/.xml)
        │
        ▼
 ┌───────────────┐   отчёт 1: «Готовность»   МОЖНО / МОЖНО С ОГОВОРКАМИ / НЕЛЬЗЯ
 │ 1. readiness  │   файл цел? какая 1С? чего не хватает?
 └──────┬────────┘
        │ человек решает, грузить ли
        ▼
 ┌───────────────┐   тестовый тенант пересоздаётся с нуля,
 │ 2. load       │   XML → JSON по типам → файлы импорта → загрузка по 15 шагам → кресла
 └──────┬────────┘
        ▼
 ┌───────────────┐   отчёт 3: «Итог»   совпало 2 587/2 587 (100%)
 │ 3. verify     │   по каждой сущности, суммы денег, каждое расхождение
 └──────┬────────┘
        │ только по явному «да» + свежий дамп
        ▼
   рабочий тенант (load --production)
```

### Шаг 1. Готовность (`readiness`)

1. `check_dump.py` ищет типичную поломку больших выгрузок: файл «начинается заново» (второй заголовок `<?xml`, обычно на 4/8/12 ГиБ) или не закрыт тегом `</V8Exch:_1CV8DtUD>`.
2. `scan_1c.py` построчно режет XML на объекты (обычный XML-парсер Python ломается после 4 ГиБ), считает объекты по типам, помеченные на удаление и проведённые, определяет период документов и конфигурацию 1С.
3. `reports.py` собирает отчёт: вердикт, таблица «что есть в 1С», чего не будет в программе и почему, что надо доработать, что предлагается дальше.

Вердикт:
- **НЕЛЬЗЯ**: файл повреждён, либо нет пациентов, счетов или записей.
- **МОЖНО С ОГОВОРКАМИ**: всё главное есть, но нет телефонов, цен, паспортов или графиков.
- **МОЖНО**: всё нужное есть.

### Шаг 2. Загрузка (`load`)

1. **Тестовый тенант пересоздаётся с нуля**: своя база `tenant<id>`, модули и права как у образца, подписка до 2222 года. Тенант помечается `fid1c_test`, и только такой тенант можно удалять и пересоздавать.
2. **Разбор** (`parse`): родной разборщик FID раскладывает XML по типам в `work/V8Exch_Data/*.json`.
3. **Сборка**: для каждого из 15 шагов сборщик FID готовит файл импорта `work/array_import/json/<шаг>.json`. Если в выгрузке нет нужных данных (например, нет регистра графиков), шаг пропускается явно, с сообщением.
4. **Загрузка по шагам** в таком порядке: branch, price, price_price, diagnoses, profession, users, employees, patient_cart, patient_passport, dependents, timetables, appointment, invoice_new, payment, payment_cart. Каждый шаг выполняется синхронно, ошибки собираются в `work/errors_<шаг>.log`, результат шага пишется в `fid1c_state.json`.
5. **Часовой пояс** клиники ставится сразу после филиала, до записей (иначе все времена сдвинутся).
6. **Кресла**: записи раскладываются по креслам без наложений, расписание врачей пересобирается по записям.
7. Сразу после загрузки запускается шаг 3.

### Шаг 3. Итог (`verify`)

`reconcile.py` сравнивает исходные объекты 1С с тем, что реально лежит в базе:

| Сущность | Что считается «совпало» |
| --- | --- |
| Пациенты | есть в базе; совпали ФИО, дата рождения, телефон и email (если есть в 1С) |
| Сотрудники и врачи | есть в базе, совпало ФИО |
| Услуги | есть в базе, совпало название |
| Записи | совпали пациент, врач, начало, конец (с учётом часового пояса) и статус |
| Счета | есть в базе, сумма равна сумме документа 1С, пациент тот же |
| Оплаты | каждая оплата (пациент + сумма) нашлась среди денежных операций |

Плюс суммы денег: счета и оплаты «в 1С / в базе». Дубли в самой 1С считаются одной записью и показываются отдельной строкой. Процент округляется вниз: 2 586/2 587 это 99.9%, а не «100%».

## 3. Что делает ассистент, а что скрипт

| Скрипт (`fid1c.py`) | Ассистент (Claude или ChatGPT) |
| --- | --- |
| проверяет файл, считает объекты, грузит, сверяет | понимает конкретную клинику и пишет раздел «Комментарий» |
| собирает таблицы и цифры отчётов | объясняет расхождения простыми словами |
| отказывает в опасных действиях | доработает импорт в коде FID, если клиника нестандартная |
| хранит состояние и журналы | спрашивает человека там, где решает человек |

Отчёты собирает скрипт, поэтому они одинаковые в Claude, в ChatGPT и без ИИ. Ассистент не может «приукрасить» итог: число N/M берётся из сверки.

## 4. Две конфигурации 1С

| | 1С:Медицина на базе УНФ | 1С:Стоматологическая клиника |
| --- | --- | --- |
| Пример | ДЕНТАЛ АСК (Челябинск) | СЕРКИН.СТОМ («Моцарт», Ижевск) |
| Пациенты | `Контрагенты` с типом «Клиенты» | `Клиенты` |
| Записи | `Событие` | `Заявка` |
| Счета | `Прием` | `ОказаниеУслуг` |
| Оплаты | `ПоступлениеДенежныхСредств` | `ОказаниеУслуг.Оплата`, `ПриходныйКассовыйОрдер` |
| Телефоны | в карточке контрагента | регистр `КонтактнаяИнформация` |
| Часовой пояс | в `СтруктурныеЕдиницы` | нет, спрашивать у клиники |

Подробности — в `fid-import-1c/references/config-unf.md` и `config-stom.md`. Конфигурация определяется автоматически по набору объектов.

## 5. Защита от ошибок

| Ситуация | Что происходит |
| --- | --- |
| Повреждённый файл | вердикт «НЕЛЬЗЯ», разбор не запускается |
| Тестовая загрузка в рабочий тенант (`1`, `lip`) | отказ, список защищённых тенантов в `fid1c.json` |
| Пересоздание тенанта, который создал не FID-1С | отказ без `--adopt` |
| Рабочий тенант: нет свежего (до 3 часов) полного дампа или нет `--yes` | отказ |
| В рабочем тенанте уже есть данные из 1С | отказ: повторная заливка задвоила бы счета и оплаты |
| Два прогона в один тенант | второй отказывает, пока идёт первый |
| Ctrl+C посреди шага | шаг помечается прерванным, продолжить его нельзя, только начать заново |
| Zip с путями за пределами папки | отказ |
| Письма, рассылки, внешние запросы | на время загрузки отключены |
| Перекладка по креслам | трогает только записи пациентов из 1С и кресла филиала из 1С |

Код выхода: 0 успех, 1 есть проблемы, 2 ошибка аргументов, 3 окружение не готово, 4 отказ по безопасности, 5 занято другим прогоном.

## 6. Что лежит в папке клиники

```
<папка клиники>/
  fid1c.json            настройки: выгрузка, путь к FID, тестовый тенант, защищённые тенанты, часовой пояс, число кресел
  fid1c_state.json      что уже сделано: шаги, результаты, время
  reports/              readiness.md, final_<тенант>.md, reconcile_<тенант>.md/.json, scan/
  logs/                 журнал каждой команды
  backups/              дампы баз
  work/                 разобранная выгрузка, файлы импорта, errors_<шаг>.log, выгрузка базы для сверки
  dump/                 распакованная выгрузка
```

## 7. Команды

```
init <выгрузка> --clinic "Название" --dir <папка> [--test-tenant id] [--timezone Europe/Samara] [--chairs 4]
doctor                              проверка окружения
readiness [--no-fid]                шаг 1
parse                               разбор XML по типам
load [--tenant id] [--steps a,b] [--resume]    шаг 2 + шаг 3
load --tenant <id> --production --backup <дамп> --yes    перенос в рабочий тенант
verify --tenant <id> | --db <база> | --export <папка> --work <папка>    шаг 3
chairs --tenant <id> [--count 4]    раскладка по креслам
backup --tenant <id>                дамп перед рабочим тенантом
extend --tenant <id> [--date …]     продлить подписку
status                              что сделано
```

| `.github/workflows/tests.yml` | автотесты на Windows и Linux при каждом push |

## 9. Как подключить

```bash
git clone https://github.com/Meldori/FID-1C.git
cd FID-1C
python tools/install.py --all        # Claude и ChatGPT/Codex
```

Дальше достаточно написать ассистенту «вот выгрузка 1С, надо перенести клинику в Future IT Dent»: навык подхватится по описанию. Подробнее о платформах: `fid-import-1c/references/platforms.md`.

## 10. Как пользоваться: пример разговора

1. Вы: «Вот выгрузка 1С клиники X, надо перенести».
2. Ассистент делает `init` и `readiness`, показывает отчёт «Готовность» и дописывает комментарий. Например: «в выгрузке нет телефонов, они в регистре, который не выгрузили, стоит попросить новую».
3. Вы: «Грузим в тест».
4. Ассистент запускает `load`. Через время показывает «Итог: 11 696/11 696 (100%)» или список расхождений с объяснением.
5. Если всё сошлось и вы согласны, ассистент делает `backup` и `load --production --yes`. Без вашего «да» этого не будет.
