# Ловушки

| Ловушка | Как узнать | Что делать |
| --- | --- | --- |
| Файл больше 4 ГБ испорчен (при выгрузке на FAT32, 32-битной 1С, передаче через удалённый доступ) | `check_dump.py`: «начинается заново» на 4/8/12 ГиБ, куски совпадают с началом | Пользователю: реальных данных только первые 4 ГБ, регистры потеряны. Просить выгрузку без ФИАС на NTFS-диск, передавать архивом 7-Zip. Перепаковка испорченного файла не помогает |
| ФИАС в выгрузке | `АдресныеОбъекты`, `АдминистративнаяИерархия` — миллионы записей, гигабайты | Для импорта не нужен; просить исключать |
| Python `xml.etree` ломается после 4 ГБ | «not well-formed» на корректной строке | `scan_1c.py` режет файл построчно — используй его |
| HTML в полях документа | `v8_DocumentObject.Прием.json` не читается | Брать данные из другого объекта |
| Часовой пояс | 1С хранит местное время без пояса, FID — UTC и переводит по поясу филиала | Пояс филиала ставить ДО загрузки записей; иначе все времена сдвинутся |
| Подписка тестового тенанта | «Срок действия истёк» | `date_end = 2222-02-02` (делает `create_tenant.php`) |
| Кэш часового пояса в Redis | Поменяли пояс, а записи грузятся со старым | `fid_run.php` сбрасывает ключи `time_zone_<tenant>_0`, `branch_id_<tenant>_0` |
| Повторная заливка | Счета и оплаты удвоились | Заливать только на откатанную из дампа базу; не запускать два прогона сразу |
| Прерванный прогон | После остановки цикл bash продолжил шаги | Проверить процессы `fid_run.php`, пересоздать тестовый тенант |
| Старый `queue:work` | Обрабатывает задачи кодом, запущенным давно | Перезапустить после правок кода |
| Пустая дата рождения | `0001-01-01` | Ставится `1970-01-01`: модель пустую дату заменяет сегодняшней |
| Служебные «пациенты» | Клиенты без имени: «Генеральная уборка», «Стрижка», «Тест» | Показать пользователю, решает он |
| Символические цены | Продажи по 1 ₽ | Не брать в цену прайса |
