# Ловушки

| Ловушка | Как узнать | Что делать |
| --- | --- | --- |
| Файл больше 4 ГБ испорчен (при выгрузке на FAT32, 32-битной 1С, передаче через удалённый доступ) | `fid1c.py readiness` (`check_dump.py`): «начинается заново» на 4/8/12 ГиБ, куски совпадают с началом | Пользователю: реальных данных только первые 4 ГБ, регистры потеряны. Просить выгрузку без ФИАС на NTFS-диск, передавать архивом 7-Zip. Перепаковка испорченного файла не помогает |
| ФИАС в выгрузке | `АдресныеОбъекты`, `АдминистративнаяИерархия` — миллионы записей, гигабайты | Для импорта не нужен; просить исключать |
| Python `xml.etree` ломается после 4 ГБ | «not well-formed» на корректной строке | `fid1c.py readiness` режет файл построчно — используй его |
| HTML в полях документа | `v8_DocumentObject.Прием.json` не читается | Брать данные из другого объекта |
| Часовой пояс | 1С хранит местное время без пояса, FID — UTC и переводит по поясу филиала | Пояс филиала ставить ДО загрузки записей; иначе все времена сдвинутся |
| Демо-счета в базе | счетов в базе больше, чем в 1С, у лишних короткие числовые `import_id` и даты 2021 года | Это демо-данные образца тенанта, не импорт: сверка считает только счета с `import_id` в виде ссылки 1С (GUID) |
| Подписка тестового тенанта | «Срок действия истёк» | `date_end = 2222-02-02` (делает `fid1c.py load` при создании тестового тенанта; рабочий — `fid1c.py extend`) |
| Кэш часового пояса в Redis | Поменяли пояс, а записи грузятся со старым | `fid_bridge.php` сбрасывает ключи `time_zone_<tenant>_0`, `branch_id_<tenant>_0` |
| Повторная заливка | Счета и оплаты удвоились | `load --production` отказывает, если в тенанте уже есть данные из 1С; два прогона в один тенант не даёт замок (код 5) |
| Прерванный прогон | `fid1c.py status`: шаг «running» | Ctrl+C останавливает и PHP; прерванный внутри шаг не продолжается (`--resume` откажет) — тест пересоздать, рабочий откатить из дампа |
| Старый `queue:work` | Обрабатывает задачи кодом, запущенным давно | Перезапустить после правок кода |
| Пустая дата рождения | `0001-01-01` | Ставится `1970-01-01`: модель пустую дату заменяет сегодняшней |
| Несколько медкарт у одного пациента | в отчёте «Медкарты»: «пациентов с несколькими картами» | В программе одно поле «номер карты»: остаётся первая по дате регистрации. Сообщить клинике список, решают они |
| Чужие реквизиты на счетах | в отчёте «Реквизиты предприятия» ✘; на счёте чужое название и адрес | Название и адрес на счетах берутся из настроек программы (`app_settings`), а не из карточки предприятия. Тенант, созданный из образца другой клиники, хранит её реквизиты: `fid1c.py requisites --tenant <id> --from-1c` |
| Служебные «пациенты» | Клиенты без имени: «Генеральная уборка», «Стрижка», «Тест» | Показать пользователю, решает он |
| Символические цены | Продажи по 1 ₽ | Не брать в цену прайса |
